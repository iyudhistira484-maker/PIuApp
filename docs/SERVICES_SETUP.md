# Aktivasi layanan PiwuApp

**Status:** jalur integrasi dan UI sudah tersedia, tetapi akun eksternal belum dikonfigurasi/diuji live dalam workspace ini. Flag `/api/status` hanya menyatakan keberadaan konfigurasi. Tidak ada kredensial, transaksi, OTP, atau deployment sungguhan yang dibuat oleh pengujian lokal.

Jangan menempelkan secret di chat. Isi environment melalui secret manager/deployment dashboard atau `.env` lokal yang diabaikan Git. Nilai `VITE_*` masuk ke bundle browser; **hanya URL dan anon/publishable key Supabase** yang boleh memakai prefix itu.

## 1. Database, akun, dan AI

1. Gunakan Supabase **staging** yang terpisah dari produksi. Backup bila database sudah berisi data.
2. Terapkan migration sekali, berurutan: `001_schema.sql`, `002_workspace_sync.sql`, `003_services.sql`, `004_project_data.sql`, lalu `005_admin.sql`. Bootstrap admin pertama mengikuti [ADMIN.md](ADMIN.md). Migration ini bukan skrip idempoten untuk dijalankan ulang.
3. Isi `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, dan server-only `SUPABASE_SERVICE_ROLE_KEY`. Aktifkan verifikasi email/nomor serta batasi signup/rate limit di Supabase.
4. Atur Site URL, redirect allowlist, email delivery, dan Google OAuth bila digunakan. Frontend dan API harus satu origin HTTPS. Isi `APP_BASE_URL` dengan origin publik sebenarnya, termasuk host preview bila menguji preview. Jangan gunakan localhost untuk tautan yang dibuka pengguna jarak jauh.
5. Isi `LLM_BASE_URL` (base kompatibel OpenAI, biasanya berakhir `/v1`) dan `LLM_API_KEY`. `LLM_MODEL` **opsional**: kalau kosong, server memakai model pertama yang dikembalikan `GET {LLM_BASE_URL}/models`. Override tier opsional: `LLM_MODEL_CEPAT`, `LLM_MODEL_SEIMBANG`, `LLM_MODEL_KUAT`. Gunakan HTTPS untuk provider eksternal.
6. Pemilih model di chat AI menampilkan **semua** model yang dilayani API key tersebut (dikelompokkan hanya untuk tampilan; vendor yang tidak dikenal masuk "Model lainnya"). Model yang dipilih dikirim apa adanya ke provider, dan respons menampilkan nama model yang menjawab. Kredit: `Ask` 1, `Plan` 2, `Builder` mengikuti tier (Cepat 1 / Seimbang 3 / Kuat 8); model provider dihitung setara Seimbang kecuali operator memetakannya lewat `LLM_MODEL_KUAT` dll. Pemilih menulis biaya tiap model dari katalog server (`costs[]` di `GET /api/ai/models`), jadi memetakan model ke tier langsung mengubah harga yang tertulis di sana — angka yang ditampilkan itu yang ditagih, termasuk estimasi di composer.
7. Restart dev server. Perubahan `VITE_*` juga memerlukan rebuild saat produksi.
8. Masuk sebagai akun nyata, buat project, tunggu **Tersinkron**. Buka **Layanan → Status → Periksa koneksi Supabase & AI**. Pemeriksaan ini menguji Auth, tabel kredit, dan endpoint daftar model; **bukan** bukti inference, multimodal, atau semua migration bekerja.
9. Setelah login sebagai superadmin, tab **AI & model** pada panel admin menampilkan status provider, pemetaan tier, katalog model dari API key, dan pemakaian kredit AI 30 hari. Tab **Operasional** menampilkan slot sandbox serta bucket rate limit (perlu migration 007). Keduanya **baca-saja**: API key tidak pernah dikirim ke browser, base URL hanya host+path, dan penyesuaian kredit tetap lewat tindakan admin dengan alasan.
10. Uji Ask, Plan, Builder, review, restore, stop, dan kegagalan provider. Plan harus berisi goal/tasks; Ask/Plan tidak dapat mengirim perubahan file. Kredit: jatah harian 20 (Free), 30 (Pro) atau 40 (Team) kredit yang direset 00:00 UTC, kredit paket hangus 2 bulan setelah terbit, top-up berlaku 12 bulan; Ask 1, Plan 2, Builder Cepat 1 / Seimbang 3 / Kuat 8. Otomatis menagih tarif tier yang benar-benar dipakai (prompt panjang/lampiran → Kuat), dan estimasi di composer menampilkan angka yang sama sebelum dikirim. Tidak ada klaim chain-of-thought: summary hanyalah ringkasan implementasi publik.

Foto → model 3D (project Roblox, mode Builder) memakai lampiran yang sudah ada: maksimum 3 lampiran per pesan (satu file atau beberapa sekaligus), semua foto diberi nomor urut di prompt (`LAMPIRAN FOTO (n)`), dan op `scene.build` wajib menyebut salah satu nomor itu. Server yang membuat geometrinya (`server/lib/lowpoly.mjs`), jadi tidak ada vertex yang dikarang model: `box`/`sphere`/`cylinder` menjadi Part Roblox, `cone`/`wedge`/`plane` (dan bentuk apa pun yang diberi `segments`) menjadi mesh, dan `asMesh: true` menggabungkan seluruhnya menjadi satu mesh (512 vertex/1.024 face, siap ekspor OBJ). Warna tiap bagian juga tidak dikarang: browser menyampel tiap foto terlampir menjadi grid 16×16 (`photoPalettes`, satu slot per foto) dan model boleh menunjuk `region` (pecahan 0–1 foto) per bagian, lalu server merata-ratakan piksel foto di area itu (`server/lib/photo-palette.mjs`). Sampel warna yang hilang/rusak membuat operasi ber-region **ditolak**, bukan ditebak. Mesh gabungan menyimpan warna per sisi (`mesh.groups`, maks. 24 grup) sehingga Preview 3D dan ekspor OBJ memakai warna foto. Batasan yang dinyatakan di prompt: ini blockout low-poly dari primitif, **bukan fotogrametri** — yang dipindahkan adalah **warna datar per sisi dari grid piksel**, dan Roblox mengabaikan warna di dalam file OBJ. Karena itu editor menyediakan **ekspor GLB bertesktur** di panel Properti objek mesh (foto project yang tersimpan di browser dibakar jadi atlas 1024×1024 berisi piksel area foto tiap grup sisi, lalu ditanamkan di satu berkas `.glb` yang dibaca importer Roblox); label UI-nya jujur menyebut **proyeksi kotak per sisi, bukan unwrap**, dan tanpa foto yang bisa dipastikan tombolnya nonaktif dengan alasan yang terlihat. Penyampelan dilakukan di browser, jadi tidak ada layanan gambar maupun kunci baru untuk fitur ini. Setelah giliran berhasil, foto yang dilampirkan disimpan sebagai **aset project di browser** (IndexedDB `piwu-project-photos`, kunci per akun+project, id dari hash isi, batas 12 foto / 16 MB per project) supaya bisa dibandingkan dengan modelnya dan dipakai lagi; tidak ada unggahan foto ke cloud dan tidak ada migration baru — payload project tetap teks yang disinkronkan dengan plafon ukurannya sendiri.

Bridge Studio memakai **plugin lokal** yang dipasang sekali dari berkas `public/plugins/PiwuStudio.rbxmx` (isi identik dengan `public/plugins/PiwuStudio.luau`; `npm run plugin:check` gagal bila keduanya berbeda, dan `npm run build` membuat ulang berkasnya). Plugin **meminta izin HTTP-nya sendiri per alamat** saat permintaan pertama (pertanyaan Allow/Deny Studio, bisa dicabut di **View → Plugin Management**); setelan _Experience Settings → Security → Allow HTTP Requests_ hanya mengatur script in-game dan bukan syarat untuk plugin. Impor `scene.roblox.json` ke Studio (`Impor scene project` → tinjau → `Bangun scene` dua kali) membuat Part/Model sungguhan dengan hierarki yang sama seperti viewport browser, satu recording Undo, dan melaporkan objek yang tidak bisa dipastikan sebagai **dilewati** (mesh kustom tanpa aset Roblox). Jalur tekstur: unduh GLB bertesktur → **3D Importer** selalu tersedia; unggah otomatis hanya bila operator memasang `ROBLOX_OPEN_CLOUD_KEY` (Open Cloud API key, scope `asset:write`) bersama `ROBLOX_ASSET_CREATOR_ID` dan `ROBLOX_ASSET_CREATOR_TYPE` (`user`/`group`) di server — kredensial itu tidak pernah dikirim ke browser, dan tanpa kunci tombolnya menjawab penolakan jujur. Unggahan Roblox tunduk moderasi (`Reviewing`/`Approved`), jadi id aset yang tersimpan di `studio.assets.json` dipakai impor scene berikutnya, bukan diandaikan langsung siap.

Mode riset (toggle **Mode riset** di toolbar komposer, diingat per akun) memakai environment terpisah: `SEARCH_PROVIDER` (`tavily`/`exa`/`brave`/`parallel`) **dan** `SEARCH_API_KEY`, keduanya wajib. Semua provider adalah pencarian web berkunci; jalur tanpa kunci (grep.app untuk kode, Context7 untuk dokumentasi) sudah dihapus, jadi tanpa kunci tidak ada pencarian sama sekali dan tidak ada hasil dari sumber anonim. `SEARCH_ENABLED=false` mematikan seluruh pencarian keluar. Ronde riset dibatasi `SEARCH_ROUNDS_MAX` (default 2, maksimum 3); setiap ronde berisi maksimum 3 kueri, berbiaya 1 kredit, dan dikembalikan bila ronde itu tidak menambah sumber baru. Model mengendalikan langkah risetnya dalam loop berbatas: bila provider mendukung **tool calling**, server mengirim skema `search`, `read_page` plus alat server baca-saja (`list_files`, `read_file`, dan `dry_run_ops` hanya untuk project Roblox di mode Builder); bila provider menolak `tools` (mis. 400), permintaan yang sama diulang sekali tanpa `tools` dan instruksi diganti ke ops JSON — satu pass, satu biaya, tanpa janji tool palsu. Alat baca-saja itu berjalan **di semua mode** (bukan hanya riset), membaca hanya berkas project yang dikirim browser, tidak menyentuh jaringan, tidak mengubah project, dan tidak menambah kredit; `TOOL_ROUNDS_MAX` (default 2, maksimum 3) membatasi jumlah rondenya, dan panggilan yang ditolak (nama tak dikenal, argumen rusak, mode/kind salah) dijawab dengan alasannya di bawah `tool_call_id` yang sama dan dilaporkan lewat `tools` pada payload balasan — tidak pernah dibiarkan tanpa jawaban. `read_page` (maksimum 3 per ronde) membuka halaman HTTPS yang dilihat model di cuplikan atau sumber bernomor yang belum terbaca; halaman yang berhasil menjadi sumber bernomor berlabel `dibuka langsung` tanpa kredit tambahan, sedangkan halaman gagal/tidak aman dilaporkan sebagai alasan, bukan sumber palsu. Setiap langkah dikirim ke browser sebagai event SSE `step` (kueri, jumlah halaman, halaman yang dibuka, alat server yang berjalan, dan pass ringkasan). Sebelum pass jawaban, server membuat **satu ringkasan abstraktif lintas halaman** (`RESEARCH_SUMMARY=false` mematikannya) dari halaman yang sudah dibaca: hasilnya masuk ke prompt jawaban sebagai bagian berlabel **bukan kutipan**, dan ke panel Sumber sebagai artefak model. Ringkasan itu divalidasi seperti keluaran model lain — nomor sumber yang tidak pernah dikembalikan dilaporkan sebagai `invalid` (bukan diselesaikan), tautan yang bukan salah satu sumber dihapus dari teksnya dan dilaporkan, dan sitasi yang hanya didukung ringkasan (bukan kata-kata halaman) ditandai `viaSummary` beserta catatannya, bukan dianggap terbukti oleh halaman. Pass ini berjalan paling banyak sekali per permintaan dan **tidak menagih kredit baru**: ia berada di dalam kredit ronde yang sedang berjalan, sehingga estimasi biaya di komposer tetap sama dengan biaya akhir turn. Tanpa provider web, permintaan pencarian web berhenti dengan 503 jujur (alasan per kueri juga tampil di chat). Baca halaman sumber memakai guard SSRF HTTPS yang sama dengan referensi URL (maksimum 8 halaman per turn, 1,5 MB per halaman, tanpa alamat privat); setiap halaman panjang dikirim ke model sebagai kutipan relevan deterministik dengan penanda `[…]`, sedangkan teks yang lebih lengkap tetap dipakai server untuk pemeriksaan sitasi. Isinya diperlakukan sebagai data tak tepercaya; jawaban akhir muncul sekaligus karena setiap pass bisa saja masih berupa permintaan pencarian. Chat menampilkan panel **Sumber** bernomor; nomor sitasi yang tidak pernah dikembalikan dilaporkan sebagai invalid, bukan dianggap sumber.

### Jawaban riset latar yang tahan restart

Turn riset tidak dibatalkan saat tab ditutup: rondenya jalan terus di server dan hasil akhirnya diklaim sekali lewat `GET`/`DELETE /api/projects/:id/ai/jobs[/:requestId]`. Job yang **sudah selesai** (`ready`/`failed`, tanpa kredensial dan tanpa prompt panjang) dimirror ke tabel `runtime_search_cache` migration 009 di bawah prefiks kunci `research-job:<projectId>:<requestId>` dengan `expires_at` sendiri, jadi proses atau instance lain yang menyajikan project yang sama bisa menyerahkan jawaban itu — dan karena barisnya dihapus saat klaim, satu jawaban tetap hanya bisa diterapkan sekali. TTL default **360 menit** (`RESEARCH_JOB_TTL_MINUTES`, di-clamp 1–10.080), maksimum 20 job dan 4 per project. `RESEARCH_JOBS_SHARED=false` mematikan lapisan bersama. Bila klien service role tidak tersedia, lapisan bersama tidak dipakai sejak awal; bila tabel 009 belum diterapkan (`42P01`/`PGRST205`/`PGRST202`), satu percobaan gagal lalu lapisan bersama dimatikan sampai restart. Galat lain (mis. izin) dihitung dan dilaporkan tanpa mematikan lapisan bersama. Selama itu pencarian dan riset tetap berjalan dengan penyimpanan per-proses, dan `/api/admin/diagnostics` melaporkan `durable:false` beserta jumlah galatnya — tidak ada klaim ketahanan yang tidak benar. Batas yang tetap berlaku: **ronde yang masih berjalan tidak dilanjutkan setelah restart** (prosesnya mati); kredit yang sempat direservasi dipulihkan `piwu_recover_credits`, bukan dihabiskan. Tidak ada migration baru untuk ini.

Rekomendasi default kami: **Tavily** — gratis untuk pemakaian pribadi sampai 1.000 kredit per bulan (1 kredit per pencarian `basic`), kontraknya paling sederhana dari keempat vendor, dan punya parameter bahasa/negara bila nanti kueri Indonesia perlu dibatasi. Parallel layak dipertimbangkan bila kuota gratis 1.000 kredit/bulan sudah terasa sempit (5.000 request/bulan gratis, Turbo $1/1K), Exa untuk kueri semantik, dan Brave hanya bila Anda memang berlangganan (tanpa free tier sejak Feb 2026).

### Verifikasi provider pencarian (panggilan nyata)

Tes unit hanya membuktikan bahwa parser cocok dengan kontrak yang kami tulis; kontrak tiap vendor dicocokkan dengan dokumentasi/SDK resmi (diperiksa 15 Okt 2026) lalu diuji ulang dengan **satu kueri nyata** memakai skrip berikut:

```bash
npm run verify:search                      # provider web yang benar-benar dipakai app
npm run verify:search -- --all             # keempat provider web: satu kueri nyata masing-masing
npm run verify:search -- --provider=exa    # paksa satu provider
npm run verify:search -- --read            # sekaligus baca halaman hasil pertama
npm run verify:search -- --json            # laporan siap-mesin
```

Setiap pemanggilan nyata memakai kuota/langganan vendor, jadi skrip hanya melaporkan apa adanya: `OK` (dengan latensi dan jumlah hasil), `GAGAL` (pesan error tanpa isi respons), atau `DILEWATI` karena kuncinya belum diisi — `DILEWATI` berarti **tidak diuji**, bukan berfungsi. Kode keluar 1 bila ada panggilan yang gagal, bila `--provider=nama` disebut tanpa kunci, atau bila `--strict` dipakai sementara ada yang dilewati. Karena keempat provider web membaca **satu** `SEARCH_API_KEY` yang sama, satu kunci tidak pernah bisa membuktikan empat vendor berfungsi: jalur default hanya menembak provider yang dipilih, dan `--all` (opt-in eksplisit keempat vendor, satu kueri nyata masing-masing) disebut apa adanya agar operator tahu kuota yang dipakai. Opsi `--kind` sudah tidak ada lagi bersama jalur tanpa kunci itu; bila tetap dipakai, skrip menjawab `DIPENSIUN` dan keluar dengan kode 1 — bukan diam-diam melewatinya. `SEARCH_ENABLED=false` membuat skrip melaporkan seluruh pemeriksaan sebagai `DILEWATI` tanpa satu pun panggilan keluar. Setiap hasil selalu didahului ringkasan konfigurasi app (provider terpilih, jenis yang tersedia, batas ronde, bias lokal) supaya jelas apa yang benar-benar diuji. Kunci dibaca dari `.env`/environment (nama yang dikenali hanya `SEARCH_API_KEY`) dan tidak pernah dicetak.

| Provider     | Endpoint                                                       | Autentikasi                                                  | Body/kueri yang dikirim                                                                                                              | Cuplikan diambil dari                                                                         |
| ------------ | -------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Tavily       | `POST https://api.tavily.com/search`                           | header `Authorization: Bearer <key>` (tanpa kunci di body)   | `query`, `max_results`, `search_depth: basic`, `include_answer: false`                                                               | `results[].content` (`title`, `url`), `score`/`raw_content` diabaikan                         |
| Exa          | `POST https://api.exa.ai/search`                               | header `x-api-key`                                           | `query`, `numResults`, `type: auto`, `contents: { highlights: true }` — tanpa `contents` Exa tidak mengirim teks halaman sama sekali | `results[].text` bila ada, jika tidak `highlights[]` (daftar string) digabung, lalu `summary` |
| Brave Search | `GET https://api.search.brave.com/res/v1/web/search?q=&count=` | header `X-Subscription-Token` (+ `Accept: application/json`) | kueri dipotong ke 50 kata (batas vendor)                                                                                             | `web.results[].description`, fallback `extra_snippets[]`                                      |
| Parallel     | `POST https://api.parallel.ai/v1/search`                       | header `x-api-key`                                           | `objective`, `search_queries[]` (**wajib** menurut skema vendor), `mode: basic`, `max_chars_total`                                   | `results[].excerpts[]` (daftar, digabung); `title` boleh `null` → diganti host                |

Semua judul/cuplikan dinormalisasi lewat pembersih yang sama (tag HTML dibuang, entitas didekode, karakter kontrol dihapus, judul ≤160, cuplikan ≤320, maksimum 8 hasil per kueri, hanya `https://`), lalu URL-nya diverifikasi ulang oleh guard SSRF saat halaman dibaca. Biaya sisi vendor mengikuti tarif masing-masing (mis. pencarian Tavily `basic` = 1 kredit vendor, Exa menghitung ambil konten per halaman) dan bisa berubah — cek dasbor vendor; yang dipastikan PiwuApp adalah **1 kredit per ronde riset** yang menambah sumber baru. Bila vendor mengubah API-nya, tes kontrak di `tests/search.test.ts` + `tests/search-api.test.ts` akan gagal sebelum pengguna melihat hasil kosong.

AI menerima maksimal 3 lampiran, masing-masing 4 MB: PNG/JPG/WebP, PDF teks (20 halaman pertama, 20.000 karakter), TXT. UI saat ini mengirim satu lampiran per pesan. `.fig` harus diekspor sebagai gambar/PDF. PDF diproses di worker dengan batas waktu 15 detik dan heap 192 MB; ini bukan isolasi OS/container. Gambar memerlukan model vision. URL referensi maksimal 2 per permintaan; UI memakai satu referensi dari tab Referensi URL. Halaman JS-only/login mungkin tidak menghasilkan konten bermakna. Clone berarti interpretasi desain orisinal, bukan salinan pixel-perfect atau pengambilan aset berlisensi.

## 2. OTP WhatsApp

- Aktifkan phone auth dan **Send SMS Hook** Supabase ke `POST {APP_BASE_URL}/api/webhooks/whatsapp`.
- Simpan signing secret hook ke `SUPABASE_SMS_HOOK_SECRET`. Implementasi memverifikasi Standard Webhooks, timestamp, ID, dan deduplikasi payload; bukan endpoint OTP tanpa autentikasi.
- Gunakan akun WhatsApp Business/Meta dengan nomor terdaftar dan **Authentication template yang disetujui**, parameter OTP pada body serta URL button. Isi `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_ID`, `WHATSAPP_TEMPLATE`, `WHATSAPP_LANGUAGE`, `WHATSAPP_GRAPH_VERSION`.
- Supabase membuat, menyimpan, mengatur kedaluwarsa, dan memverifikasi OTP. PiwuApp tidak membuat kode fallback. Tombol login menggunakan channel SMS Supabase yang delivery-nya dialihkan oleh hook ke WhatsApp.
- Uji consent penerima, format E.164, expiry, resend/rate-limit, signature salah, hook replay, kegagalan Meta, dan verifikasi kode salah. `processing` yang tertinggal akibat crash harus diperiksa operator sebelum retry; jangan menghapus receipt secara sembarangan.

## 3. Sandbox, npm, dan Lighthouse

1. Siapkan akun E2B dan `E2B_API_KEY` server-only. Eksekusi kode user **tidak pernah** memakai shell host PiwuApp.
2. Bangun template Node 22 + Chromium + Lighthouse dengan skrip administrator:
   ```sh
   node --env-file=.env scripts/build-sandbox-template.mjs
   ```
   Skrip ini menggunakan SDK E2B terpasang; belum dijalankan live di sini. Build template menggunakan infrastruktur akun Anda dan dapat dikenai biaya. Jangan memasukkan secret lain dalam image, build context, atau environment template.
3. Isi `E2B_TEMPLATE` dengan alias yang dihasilkan (default skrip `piwuapp-node-audit`). Template mengatur `CHROME_PATH=/usr/bin/chromium`.
4. Terminal menjalankan shell non-interaktif, maksimal 90 detik per perintah; 1 kredit. Ini bukan PTY/persistent shell session. Direktori kerja tetap `/home/user/project`; perubahan `cd`/shell variables tidak bertahan antarperintah.
5. **Layanan → Paket** mencari registry npm, install/uninstall, preview eksternal, impor snapshot, dan stop. Install/preview 2 kredit. `npm install --ignore-scripts` menghindari lifecycle script saat instalasi; paket yang benar-benar membutuhkan postinstall dapat gagal dan perlu ditinjau.
6. Perubahan `package.json` dapat dipulihkan melalui versi. Perubahan dari shell **tidak otomatis mengganti editor**; gunakan **Impor perubahan sandbox** dengan konfirmasi. File biner, secrets, build, node_modules, file >256 KB, atau snapshot >4 MB tidak diimpor. Edit cloud yang baru menyinkronkan path terkait ke sandbox dan dapat mengganti perubahan shell yang belum diimpor.
7. Sandbox TTL 10 menit, maksimal dua sesi aktif per akun dalam satu proses API. Sesi hilang setelah restart API; batas global/sesi masih in-memory, sehingga deploy awal harus satu instance. Preview sandbox dapat diakses pemegang URL sampai sandbox berhenti.
8. Lighthouse menjalankan build nyata di sandbox, 3 kredit. Hasil asli disimpan dalam `scan_reports`; tidak ada skor sintetis. Audit gagal bila template/browser belum siap. Laporan Lighthouse upstream dapat memuat judul bahasa Inggris.

## 4. Kolaborasi

- Owner membuat undangan Viewer/Editor di Layanan → Anggota. Tautan sekali pakai, SHA-256 di database, 7 hari. Undangan dengan email harus diterima oleh akun dengan email yang sama dan sudah diverifikasi.
- Email opsional melalui `RESEND_API_KEY` + `EMAIL_FROM` dari domain terverifikasi. Jika email gagal, UI tetap menampilkan tautan dan mengatakan email belum terkirim.
- Owner mencabut undangan/membership; API juga mendukung perubahan role. Owner tidak dapat diubah melalui endpoint anggota.
- Migration 003 menambahkan policies kanal private Realtime dan publication `project_workspaces` bila Supabase Realtime tersedia. Uji RLS kanal pada Supabase asli. Presence hanya indikasi kehadiran, bukan bukti identitas/cursor terverifikasi.
- Perubahan remote memicu antrean sync yang sama dengan fallback polling. Konflik revisi tetap eksplisit. Sejak tahap 10, dua tab yang membuka **file yang sama** juga menggabungkan karakter lewat CRDT kecil selama sesi aktif (≤30.000 karakter, dasar teks harus sama); baris data aplikasi dan file yang tidak dibuka rekan tetap memakai revisi, bukan penggabungan simultan.
- Komentar cloud memiliki author_id dari JWT, terpisah dari komentar demo dalam snapshot notebook.

## 5. Publish, domain, analytics — tidak tersedia

- PiwuApp adalah **app builder**, bukan layanan hosting: tidak ada deploy website, domain kustom, SSL, rollback, atau analytics pengunjung. `NETLIFY_TOKEN`, route `/publish`, `/deployments`, `/analytics`, dan worker publish sudah dihapus dari server.
- Jalan keluar kode tetap ada: **Export ZIP** di toolbar workspace (dan menu project). Project Roblox dipublikasikan lewat **Roblox Studio/plugin**, bukan lewat PiwuApp; build native memakai Expo/EAS di mesin Anda.
- Tabel lama `project_sites`, `deployments`, `publish_jobs`, dan `analytics_events` dibiarkan **inert** di skema 003 supaya migration tidak berubah; aplikasi tidak lagi membaca atau menulisnya. Template marketplace baru selalu menyimpan `preview_url` kosong.

## 6. Pembayaran, kredit, referral, marketplace

- Mulai dari **sandbox provider**, bukan pembayaran nyata. Set `PAYMENT_PROVIDER=midtrans` atau `xendit`.
- Midtrans: isi `MIDTRANS_SERVER_KEY`; `PAYMENT_LIVE=false` memakai sandbox endpoint. Notification URL: `/api/webhooks/payments/midtrans`. Signature SHA-512 diverifikasi, lalu status diambil ulang ke API provider.
- Xendit: isi `XENDIT_SECRET_KEY` test-mode dan `XENDIT_WEBHOOK_TOKEN`. Invoice callback: `/api/webhooks/payments/xendit`. Test/live Xendit ditentukan jenis API key; **flag PAYMENT_LIVE tidak mengubah mode key Xendit**. Token callback diperiksa dan invoice dibaca ulang server-side.
- Harga/kredit berasal dari katalog server, bukan request client. Webhook/refresh mengecek ID, amount, IDR, dan settlement. Browser redirect tidak menambah kredit. Pemenuhan transaksi idempoten melalui row lock dan ledger unik.
- Pro Rp199.000/1.500 kredit + 30/hari; Team Rp499.000/4.500 kredit + 40/hari; top-up 300 Rp49.000, 1.400 Rp199.000. Paket prabayar 30 hari, tidak auto-renew; jatah harian direset 00:00 UTC dan tidak menumpuk, kredit paket hangus 2 bulan setelah terbit, top-up berlaku 12 bulan. Pembelian paket berikutnya dijadwalkan setelah periode sebelumnya; kredit langsung ditambahkan. Tidak ada prorata upgrade. **Pembatasan fitur per paket bersifat opsional dan bawaannya terbuka**: semua paket memakai builder, template, AI, dan kolaborasi yang sama karena matriks di panel admin masih "Semua paket" untuk sandbox, Studio bridge, dan penjualan template; kredit tetap pembatas penggunaan yang aktif, dan kartu paket menyebutnya (`planBenefits()`). Bila operator menaikkan baris matriks, server menolak permintaan dari paket di bawahnya (`PLAN_REQUIRED`), bukan hanya menyembunyikan tombol. Harga dan kredit paket dapat diubah superadmin dari **Pengaturan situs**; nilai disimpan di `site_configuration.value.enabled_services.plan_overrides` (tanpa migration baru), lalu dipakai checkout, `/upgrade`, dan landing. Jatah harian, plafon Free, dan masa berlaku tetap kebijakan migration 010.
- PiwuApp **tidak menyediakan refund**; semua pembelian bersifat final. Callback provider yang menyatakan refund/chargeback tetap diproses sebagai pembatalan: kredit, entitlement, revenue, dan bonus referral terkait dicabut dan saldo bisa negatif. Status `review` dipakai untuk rekonsiliasi manual. Xendit refund lifecycle di luar invoice callback **belum otomatis**; operator harus melakukan rekonsiliasi. Jangan mengaktifkan uang nyata sebelum alur ini memenuhi kebijakan bisnis dan diuji provider.
- Referral diklaim akun terverifikasi dalam 7 hari, sebelum pembayaran pertama. Bonus 50 untuk kedua akun setelah pembelian paket/top-up minimal Rp49.000; pembelian template tidak menghasilkan bonus. Anti-fraud multiakun memerlukan kontrol tambahan sebelum promosi publik.
- Marketplace mempublikasikan snapshot kode, tanpa chat, ledger, atau env_vars. Snapshot berbayar hanya dikirim ke pemilik/pembeli dengan entitlement. Pendapatan bersih 80% dicatat, bukan langsung dibayarkan. **Payout, KYC, sengketa, dan moderasi ditinjau manual; refund tidak disediakan.**

## 7. Secrets, storage, rekaman

- Buat `SECRETS_ENCRYPTION_KEY` 32 byte acak dalam format 64 hex melalui secret manager. AES-256-GCM memakai nonce acak dan AAD project/environment/key. Backup/rotasi master key harus dikelola operator; kehilangan key berarti tidak dapat mendekripsi data.
- UI hanya menerima input dan menampilkan nama/environment. Tidak ada read-plaintext endpoint. Ini **bukan KMS envelope encryption** dan secret tidak otomatis diinjeksikan ke aplikasi statis/E2B.
- Storage memakai bucket privat `project-assets`; URL signed berlaku 5 menit. Validasi signature file bukan antivirus/DLP lengkap.
- Rekaman berupa snapshot kode dan label aksi, bukan video. Disimpan di IndexedDB, dipisahkan berdasarkan akun/project di UI; bukan enkripsi browser. Timeline memiliki play/pause/scrub/speed dan preview terisolasi.
- Owner dapat membagikan rekaman setelah konfirmasi review data; tautan read-only 7 hari, dapat dicabut. Kode tetap dapat disalin penerima selama tautan aktif. Maksimal 100 snapshot/4 MB.

## 8. GitHub push (opsional)

- Push berjalan dari browser ke `api.github.com`; server PiwuApp tidak menerima atau menyimpan token GitHub.
- **OAuth**: aktifkan provider GitHub di Supabase (Authentication → Providers), isi Client ID/Secret dari GitHub OAuth App, dan tambahkan origin aplikasi ke redirect allowlist. Cakupan yang diminta `repo` (repo privat + izin tulis). Setelah kembali, `provider_token` tersedia di sesi Supabase di browser.
- **Tanpa OAuth**: buat fine-grained PAT untuk repositori tujuan dengan izin **Contents: read and write** (classic: `repo`), lalu tempel di dialog **Repositori**. Token hanya disimpan di memori tab dan hilang saat halaman ditutup; jangan menempelkannya di chat/log.
- Yang dikirim: file teks project (maksimum 200 file / 4 MB per push). Gambar, GLB, ZIP, dan `.env` dilewati; file yang dihapus di PiwuApp tidak dihapus dari GitHub. Repositori harus sudah ada; cabang dibuat bila belum ada.
- Batas: satu arah (tanpa pull/PR/webhook), tanpa pembuatan repositori, dan setiap push membuat satu commit di cabang yang dipilih.

## 9. Menjalankan dan acceptance staging

```sh
npm ci
npm test
npm run build
npm start             # frontend + API satu proses, default port 3001
# atau npm run dev    # Vite 3001 + API 3002
```

Pasang HTTPS reverse proxy, body/concurrency limits, HSTS/CSP yang kompatibel Monaco/preview, dan origin yang benar. Set `TRUST_PROXY_CIDRS` hanya ke proxy milik Anda; jangan trust-all. In-memory rate limit dan sandbox map bukan koordinasi multi-instance. Queue publish dan ledger sudah database-backed.

Acceptance wajib sebelum go-live:

- Empat akun: Owner/Editor/Viewer/outsider, termasuk pencabutan akses, token palsu/expired, dan dua akun dalam browser yang sama.
- Supabase Auth/PostgREST/Storage/Realtime sungguhan; login Google dan WhatsApp pada perangkat penerima.
- AI teks/gambar/PDF, Plan, stop/disconnect, secret output, insufisien kredit, provider timeout.
- Sandbox install, edit melalui shell, import/restore, expiry, stop; Lighthouse berhasil dan gagal; Export ZIP; hapus project saat build.
- Provider payment sukses, pending, expired, callback berulang/out-of-order, amount mismatch, chargeback, dan rekonsiliasi gagal jaringan. Jangan gunakan kartu/dompet nyata untuk tes pertama.
- Beli template sebagai akun kedua; sumber tidak dapat diambil sebelum bayar; revoke share rekaman; tidak ada secret muncul pada bundle/log/preview.
- Pantau `credit_reservations`, `payment_orders`, `webhook_receipts`; siapkan alert, backup, kebijakan retensi, dan runbook operator.

Lingkungan coding ini belum memiliki akun/kredensial layanan tersebut dan koneksi keluar dibatasi. Hasil unit/mock/PostgreSQL lokal tidak boleh dianggap verifikasi provider live.
