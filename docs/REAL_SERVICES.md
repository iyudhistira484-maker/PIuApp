# Aktivasi layanan nyata

## Kondisi saat ini

Jalur demo bukan lagi pintu masuk aplikasi. Membuka `/projects`, `/project/:id`, `/admin`, atau halaman layanan tanpa sesi akun mengarah ke login. Project lama tidak dihapus: login nyata lalu impor data legacy secara eksplisit dari dialog Penyimpanan.

Pemeriksaan terakhir di lingkungan kerja: Supabase Auth dan database tidak dapat dijangkau oleh backend. Kredensial AI, E2B, pembayaran, WhatsApp, dan master key enkripsi belum tersedia. Ini adalah blocker operasional, tidak dapat diperbaiki dengan mengganti label atau membuat hasil tiruan.

## Urutan aktivasi yang diperlukan

1. **Jaringan dan Supabase:** jalankan backend di lingkungan yang dapat menjangkau project Supabase. Isi `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` melalui environment/secret manager. Jangan tempel secret di chat, source, atau file project pengguna. Jalankan migration `supabase/001_schema.sql` sampai `005_admin.sql` sesuai urutan. Atur URL redirect Auth untuk domain aplikasi; aktifkan provider login yang dipakai. Lihat CLOUD_SETUP.md dan ADMIN.md untuk RLS/bootstrap administrator.
2. **AI:** isi `LLM_BASE_URL` (base URL kompatibel chat/completions) dan `LLM_API_KEY`; `LLM_MODEL` opsional (default = model pertama dari `/models`), begitu pula model per tier. Pemilih model di chat menampilkan seluruh model milik API key itu; panel admin **AI & model** menampilkan status provider, pemetaan tier dan katalog yang sama secara baca-saja (API key tidak pernah dikirim ke browser). Endpoint menggunakan JWT akun, membership Editor, pemeriksaan platform dan saldo kredit. Uji Ask → Plan → Builder pada project yang tersinkron; cek versi sebelum/sesudah dan reserve/settlement kredit. Jangan menganggap hasil `/models` menjamin inference berhasil. Untuk project Roblox, balasan Builder dapat memuat `ops` `scene.transform` yang diterapkan server secara deterministik pada `scene.roblox.json` (batch semua-atau-tidak, target per ID/nama); batch yang ditolak tidak mengubah scene dan alasannya tampil di chat.
   2b. **Riset & pencarian (opsional):** wajib mengisi keduanya — `SEARCH_PROVIDER` (`tavily`, `exa`, `brave`, `parallel`) dan `SEARCH_API_KEY`. Tanpa kunci tidak ada pencarian sama sekali: jalur tanpa kunci (grep.app untuk kode, Context7 untuk dokumentasi) sudah dihapus, jadi permintaan sumber berhenti dengan 503 jujur sebelum satu ronde pun ditagih — bukan hasil kosong, bukan sumber anonim, dan bukan jawaban tanpa sumber. `SEARCH_ENABLED=false` mematikan seluruh pencarian keluar. Ronde dibatasi `SEARCH_ROUNDS_MAX` (default 2); tiap ronde = 1 kredit dan dikembalikan bila ronde itu tidak menambah sumber baru; pembacaan halaman memakai guard SSRF HTTPS yang sama dengan referensi URL dan isinya diperlakukan sebagai data tak tepercaya. Verifikasi nyata: jalankan `npm run verify:search` (satu kueri asli per provider yang kuncinya terisi; `--provider=exa`, `--read`, `--json` opsional) — skrip melaporkan OK/GAGAL/DILEWATI apa adanya dan tidak pernah mencetak kunci. Kontrak tiap vendor yang sudah dicocokkan dengan dokumentasi resmi ada di `docs/SERVICES_SETUP.md`. Ringkasan lintas halaman (`RESEARCH_SUMMARY=false` untuk mematikannya) berjalan sebagai satu pass model tambahan **di dalam** kredit ronde yang sedang berjalan, jadi tidak ada kredit baru; alat server baca-saja (`list_files`, `read_file`, `dry_run_ops` — yang terakhir hanya untuk project Roblox di mode Builder) berjalan di semua mode tanpa kredit, tanpa jaringan, dan tanpa menulis project, dengan batas `TOOL_ROUNDS_MAX` (default 2, maksimum 3). Setelah itu barulah uji manual: nyalakan toggle Mode riset di composer, ajukan pertanyaan yang butuh sumber terbaru, lalu periksa panel Sumber (termasuk blok ringkasan yang berlabel "bukan kutipan") dan laporan sitasinya.
3. **Runtime/terminal:** isi `E2B_API_KEY` dan template yang sesuai (`E2B_TEMPLATE`). Perintah dijalankan di sandbox terisolasi dengan batas waktu; tidak ada akses shell host. Terminal saat ini non-interaktif, bukan PTY persisten. Cek output/exit code asli serta perubahan file melalui mekanisme import snapshot; jangan menganggap shell otomatis menyimpan perubahan ke cloud.
4. **Publikasi (di luar PiwuApp):** PiwuApp tidak menghosting hasil build. Unduh **Export ZIP** lalu jalankan di hosting pilihan Anda; project Roblox dipublikasikan dari Roblox Studio. `APP_BASE_URL` tetap dipakai untuk redirect pembayaran, bukan untuk deploy.
5. **Secrets:** buat master key AES-256-GCM 32 byte (64 hex) melalui secret manager untuk `SECRETS_ENCRYPTION_KEY`. Simpan cadangan secara aman; jangan merotasi tanpa rencana migrasi ciphertext yang sudah ada. PiwuApp tidak membuat key sementara yang berpotensi membuat secret lama tak terbaca.
6. **Pembayaran/WhatsApp/email:** ikuti SERVICES_SETUP.md. Lakukan verifikasi provider sandbox, signature callback dan idempotency sebelum mengaktifkan transaksi live. Mode sandbox provider bukan pembayaran uang nyata. Aktivasi ini tidak dilakukan otomatis dan tidak mengirim transaksi/pesan pada pemeriksaan kesiapan.

## Pemeriksaan setelah konfigurasi

- Restart backend setelah perubahan environment dan rebuild frontend jika variabel `VITE_` berubah.
- `GET /api/public/readiness`: hanya auth health dan tiga tabel inti diperiksa; hasil di-cache 30 detik. Status `configured_unverified` menunjukkan keberadaan konfigurasi, bukan koneksi provider live. Status `reachable` tidak menggantikan uji RLS dan seluruh migrasi.
- Login akun terverifikasi, buat project, tunggu “Tersinkron ke cloud”, buka di browser kedua dengan akun yang sama. Ubah file dan pastikan perubahan remote diterima tanpa menimpa draft konflik. Supabase Realtime publication dipasang oleh migration 003; koneksi gagal memakai polling, bukan kolaborasi palsu.
- Uji akun Viewer tidak dapat menulis/AI/audit, dan akun lain tidak dapat membaca project privat.
- Jalankan satu inference nyata, satu perintah shell nyata, lalu satu Export ZIP. Periksa hasil layanan dan ledger, bukan hanya perubahan teks UI.

Pengujian otomatis menggunakan fixture jaringan yang terisolasi di `tests/` dan tidak disertakan di aplikasi. Itu bukan bukti bahwa provider eksternal sudah aktif. Seluruh daftar sisa implementasi terdapat di STATUS.md; “tanpa demo” belum sama dengan “semua fitur produksi tuntas”.
